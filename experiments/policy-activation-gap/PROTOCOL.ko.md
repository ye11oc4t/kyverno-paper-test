# 정책 활성화 승인 간격 실험 계획

정책 도구의 API 객체가 성공적으로 생성됐다는 응답은 정책 문법이 수락됐다는 뜻이다. 이 응답이 실제 집행 준비 완료까지 뜻하는지는 별개의 문제다. Kyverno, Gatekeeper, Kubewarden은 정책 객체를 저장한 뒤 컨트롤러가 정책을 컴파일하거나 내부 엔진에 적재하고 웹훅 구성을 갱신한다. 이 과정은 비동기로 진행된다.

본 실험은 정책 생성 성공 응답 직후부터 첫 정책 거부가 관찰될 때까지를 활성화 간격으로 정의한다. 무해한 ConfigMap만 사용한다. 각 라운드의 정책은 고유한 라벨 값만 거부하고, 거부 메시지에도 라운드 식별자를 넣는다. 정책 생성과 첫 객체 생성은 미리 연결해 둔 동일 HTTPS 연결에서 연속으로 수행해 클라이언트 프로세스 시작 지연을 줄인다.

첫 객체가 허용된 뒤 준비 확인용 서버 측 드라이런이 같은 정책 메시지로 거부되고, 준비 후 대조 객체도 거부되면 해당 라운드에서 활성화 간격이 실증된 것이다. 준비 후 대조 객체가 거부되지 않으면 정책 자체 또는 실험 구성이 잘못된 것이므로 그 라운드는 유효하지 않다. 첫 객체가 곧바로 거부된 경우에는 그 환경에서 간격을 관찰하지 못한 것이며 원자적 활성화를 입증한 것으로 해석하지 않는다.

비교 대상은 Kubernetes 기본 ValidatingAdmissionPolicy v1.35.8, Kyverno v1.19.1, Gatekeeper v3.23.1, Kubewarden v1.37.2이다. 모든 도구는 새 kind 클러스터에서 독립적으로 실행한다. 결과에는 정책 생성 응답, 즉시 요청 응답, 준비 확인의 모든 시도, 준비 후 대조 응답, 준비 후 정책 상태, API 서버 감사 로그를 보존한다.

이 실험이 입증할 수 있는 것은 성공적인 정책 생성 응답과 실제 집행 사이에 관찰 가능한 간격이 존재하는지 여부다. 간격의 부재, 모든 배포 환경에서의 재현성, 공격 성공 가능성, 제품의 보안 취약점 등급은 이 실험만으로 주장하지 않는다.
