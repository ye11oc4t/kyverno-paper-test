# 파일럿 재검토와 확장 v2

측정 전 고정: 2026-09-19 KST. 기존 결과는 보존하고 v2 실행을 별도 기록한다.

v1의 72/72는 명시적으로 두 경로를 포함한 사용자 정의 정책의 기능 확인이었다. 엔진당 8개 사례 중 두 규칙의 적합 입력이 중복됐다. 경로를 포함한 컨테이너 설정은 6종이고, 세 번 반복을 독립 표본으로 볼 수 없다. 모든 유형을 직접 검사하도록 작성한 정책의 성공을 배포된 공개 정책의 포괄성으로 확대할 수 없다.

v2의 엔진당 24개 사례는 반복 없이 실행한다. 일반·Ephemeral 경로마다 단일 적합, 복수 적합, 유효한 경계 이름, 첫·마지막 요소의 이름 부적합, 이름 중간 접두사, 구분자 없는 이름, 첫·마지막 요소의 이미지 부적합, 한 요소의 두 규칙 부적합, 서로 다른 요소의 각각 부적합을 평가한다. 추가 두 사례는 기존의 정상 Ephemeral Container가 있을 때 후속 적합·부적합 추가 요청이다. 실행 순서는 고정 seed 20260919로 섞는다.

이름과 이미지 식별자만 변하며 모든 이미지 내용은 동일한 무해한 pause이다. 기존 보안 통제를 유지한다. 거부한 복수 요소 요청은 부분 저장이 없어야 하고 기존 컨테이너 목록도 유지되어야 한다. 적합 요청은 모든 새 시험 컨테이너의 저장·시작을 확인한다. 두 규칙이 동시에 부적합할 때는 해당 규칙 중 하나 이상의 명시적 거부를 요구하고, 모든 오류를 열거해야 한다고 요구하지 않는다.

Admission 비교에는 VAP, Kyverno CEL ValidatingPolicy, Gatekeeper Rego에 Kubewarden CEL/WASM을 추가한다. Kubewarden은 독립 배포·집행 구현을 더하지만 CEL 기반 도구들이 완전히 독립적인 평가 언어를 사용한다는 뜻은 아니다. Polaris는 동일한 가상 객체의 JSON Schema 정적 검사로 추가하며 Admission 호출·거부·런타임 결과로 합산하지 않는다.

이번 v2 역시 기능과 상태 보존을 평가한다. 기본 제공 보안 정책의 누락, 장애 상황, 접근 권한, 권한 상승, 전체 생태계의 결함률을 평가하지 않는다. 공개 정책 조사는 계약·설정·평가 단계의 문서상 차이를 검토하고 제품 결함과 혼동하지 않는다. 제품이나 언어 수만 늘려 연구의 독립성이 확보됐다고 주장하지 않는다.
